# Security audit (4 November 2026)

Scope: branch `launcher-phases-1-4` at `318f81a` (the built-in meeting point and relay-only matches). Four separate
reviews, each by an agent that had not seen the code being written. They covered:

1. The launcher on the player's own computer: its local web server, its API, the page and the programs it starts.
2. The servers that face the internet: the game server, the meeting point, the relay and the lobby.
3. The friends system: the service, its moderation console and its encryption.
4. Downloads, self-update, the release workflow, router (UPnP) and firewall changes, and the `deploy/` files.

Each finding was then fixed with a regression test, and the whole suite run again.

How it was checked:

- Reading the code, plus proof-of-concept scripts run against real servers.
- The encryption was checked against the RFC 7748, 8439, 5869, 4226 and 6238 test vectors, and against the
  `cryptography` library.
- `git ls-remote` was used to confirm every pinned GitHub Action commit.
- Tracked files and history were searched for keys and tokens. None were found; the only match is the code that
  generates certificates.

The launcher and servers use only Python's standard library, plus `psutil` in one place.

Not covered: Windows itself, the built exe, and the meeting point running on Lightsail. The cloud connection needed
signing in again, so that server's open ports were not re-checked.

Results: before, 887 tests passed. After, 967 pass (981 with the same-day follow-ups) (4 skipped, Windows-only); `tools/validate_repository.py`,
`tools/check_links.py` and `tools/check_ui_syntax.js` are clean.

## Fixed

### High

- **The friends service could get a room's server code.**
  - *What was wrong:* the app sealed the code for whatever friends and keys the service listed. An operator could add a
    made-up "friend", or swap a real friend's key, and open the code.
  - *Now:* codes are sealed only to the key pinned for a friend, and only for friendships this app added or accepted
    itself (`trusted_key`, `_approved` in `launcher/friends.py`). An invite with a server code is refused otherwise.
  - Test: `tests/test_friends_operator.py`.

- **A swapped key let the service read new messages.**
  - *What was wrong:* the app sealed to the service's latest key; a changed key only showed a banner.
  - *Now:* after a key change, nothing is sealed for that person (direct or group) until the player taps "We compared
    it, it matches". Group chats got that button too (`verify_group`).
  - Test: `tests/test_friends_operator.py`.

- **A friend could wipe the other person's evidence.**
  - *What was wrong:* removing, blocking or leaving the service deleted the other side's copy of the conversation and
    made a report impossible.
  - *Now:* only the caller's own copy is deleted. Someone who leaves is remembered for the usual week, so they can
    still be reported (`server/social/__init__.py`).
  - Test: `test_nobody_can_wipe_the_other_side_or_escape_a_report`.

- **Uninstall could delete a whole folder the player picked for logs**, such as Documents or a whole drive.
  - *Now:* a logs folder outside the data folder keeps everything except Legacy Player's own log files
    (`log_paths` in `launcher/selfuninstall.py`).
  - Test: `tests/test_uninstall_logs_folder.py`.

- **A client that never read its answers held a server slot forever.**
  - *Now:* every write has a time limit (20 s, never past the connection's lifetime), and the write buffer is capped
    (`server/api/json_server.py`, the relay, and the meeting point).
  - Test: `StalledReaderTests`.

- **Unbounded IDs blew up memory and snapshots.**
  - *What was wrong:* 60 KB IDs, repeated, made 166 MB snapshots and stalled the server for 2 seconds.
  - *Now:*
    - IDs and text are capped, and control characters are refused.
    - The removed-members list is capped.
    - A full replay recorder writes one "truncated" event instead of leaving a room half-changed.
    - Autosave writes in a worker thread.
  - Test: `BoundedInputTests`.

### Medium

- **The service could relabel or replay messages.**
  - *What was wrong:* the app showed whatever thread and author the service said.
  - *Now:* each message is opened against the thread the app asked for and its row's author, and a repeated message
    id is shown once.
  - Test: `tests/test_friends_operator.py`.

- **Everyone arriving through a meeting point shared one budget.**
  - *What was wrong:* together they had one connection cap and one lockout bucket. Eight wrong keys locked every
    meeting-point friend out.
  - *Now:*
    - They get their own share of connections (64 of 128).
    - The shared bucket is never locked out. It is still slowed to a rate that makes guessing a key take thousands of
      years.
    - Meeting-point friends get a larger window for new friend identities, and a new service-wide limit of 300 an
      hour always holds, even behind a proxy.
  - Tests: `MeetingPointShareTests`, `tests/test_friends_hardening_2026_11.py`.

- **Connections could be held open without logging in.**
  - *Now:*
    - At most 8 pending TLS handshakes per address (an IPv6 /64), 512 in all.
    - The open-file limit is raised at start.
    - The meeting point parks at most 64 connections per network (IPv4 /24, IPv6 /48).
  - Test: `HandshakeAndParkingTests`.

- **A kicked player kept their open relay pipe.**
  - *Now:* the relay tracks pipes per member and closes them on kick or leave. Membership is checked again before
    pairing.
  - Test: `RelayMembershipTests`.

- **A moderator account's lockout could be wiped.**
  - *What was wrong:* a flood of made-up login names cleared it.
  - *Now:* only old entries for names that are not accounts, and not locked, are dropped.
  - Test: `test_a_flood_of_made_up_names_keeps_a_real_lock`.

- **A crafted tag name could run code in the release workflow.**
  - *Now:*
    - No `${{ }}` inside scripts.
    - Every action is pinned to a commit SHA, and no checkout keeps credentials.
    - Build and test run read-only; signing has only the Azure sign-in; publishing is a separate job that runs no
      repository code.
    - The build's Python packages are hash-locked (`requirements-build.txt`).
  - Test: `tests/test_supply_chain_2026_11.py`.

- **Router (UPnP) requests could be redirected anywhere on the network or the internet.**
  - *Now:* no redirects, no proxy, the router must be a private address next to this computer's, sizes are capped, and
    XML with a DTD is refused.
  - Test: `PortMapHardeningTests`.

- **The firewall helper ran a script from `%TEMP%` as administrator.** Another program could swap that script before
  the approval click.
  - *Now:* there is no script file. One elevated PowerShell, by its full path, runs netsh with everything on its
    command line. Non-ASCII user folders survive.
  - Test: `tests/test_hardening.py`.

### Low

- **The staged self-update was not checked again before it was copied in.** `apply.ps1` now checks a manifest of
  SHA-256 sums first.
- **DAT files in UTF-16 got past the entity check.** Entity and DTD declarations are refused in any encoding.
- **Downloads could follow redirects to other sites.** Game card lookups follow redirects only to https Wikipedia or
  Wikidata. 7-Zip and tar are found by full path, never in the current folder.
- **Pins and secrets.**
  - Reaching a player's server through a meeting point needs an 80-bit pin.
  - A secret file that is empty or the wrong length is regenerated.
  - An empty admin token is refused.
- **Throttle tables and the invite cap.** The lockout table is bounded without letting a flood free a real lockout.
  The server-wide limit on bad invites went from 40 to 2000 a minute.
- **The launcher page.**
  - The CSP now blocks framing, `<base>`, form posts and plugins.
  - Covers (whose address carries the run's token) are no longer cached.
  - Idle connections end after 60 s.
  - Links and images can only be https or this server's own pages (`safeUrl` in `index.html`).
- **Moderator set-ups.** A set-up in progress can't be replaced through another invite.
- **Deploy files.** The Caddy container drops all capabilities. The systemd unit is sandboxed (exposure 2.0).
  `deploy/setup-vps.sh` installs the newest release tag instead of `main`.

## A second review of the fixes

A fresh reviewer read the whole fix commit (`42ed871`) for regressions. It found five, all fixed with tests the same day:

- **Rooms refused some players.** The new id limit (64 characters, printable only) refused long display names and
  emoji with joiners. Ids may now be 128 characters (game ids 256), and only control characters and line breaks are
  refused. Very long game titles get a shortened id at the launcher.
- **An unreadable secret file was replaced.** A secret file that couldn't be read for a moment (Windows antivirus or a
  lock) got a fresh secret, which broke every code already handed out. Now the server stops instead, as before; only a
  file of the wrong length is replaced.
- **Friends could be wrongly left unconfirmed.** Typing the code of someone who was already a friend, or who had asked
  first, did not count as confirming them. Requests sent before the update were not counted either. The service now
  names the friend in its answer, and requests already sent count on the first run.
- **Report-and-block on someone who left showed an error.** Retrying then filed the report twice. Now the report is
  filed and the block is skipped.
- **Unchecked records of players who left.** The new record was loaded from disk without checks; it is now checked
  field by field. Pending moderator set-ups are compared without case, like account names.

## Checked and safe

- **The launcher's local server.** It refuses DNS rebinding (exact Host match, loopback only) and cross-site requests
  (custom header plus JSON, no CORS). It rejects path traversal for covers, and the session secret works once.
- **The page.** There is no HTML injection: `h()` only makes text nodes and attributes, and the one `innerHTML` takes
  static SVG.
- **Programs and files.** Programs start from argument lists, never a shell. Zip-slip is refused in every unpacker and
  in save restores.
- **Encryption.** It passes the RFC test vectors. No nonce is ever reused; keys and messages are bound to the
  conversation, the sender and the message id; and every secret is compared in constant time.
- **The moderation console.** Every field is escaped, the cookie is HttpOnly and SameSite=Strict, writes need a CSRF
  token, logins use scrypt with TOTP, and a TOTP code can't be used twice.
- **Meeting-point traffic.** A friend's traffic through a meeting point is encrypted end to end and pinned to the
  player's server. The meeting point can neither read it nor change it.

## Still open (needs a decision or the owner's hands)

1. **Self-update trusts whoever can publish a GitHub release.** *Follow-up the same day:* update signing is built and
   tested, but switched off until you make a key. With it, the app checks an Ed25519 signature over the tag, file name
   and SHA-256 (`launcher/ed25519.py`, matched against the RFC 8032 vectors), and the workflow signs the zip with the
   secret `LP_UPDATE_SIGNING_KEY` (`tools/sign_release.py`). To switch it on, make a key with
   `python tools/sign_release.py new-key`, add the secret, and list the public half in `launcher/version.py`
   (`docs/RELEASE.md`, "Update signing"). Until then nothing changes. *Switched on 2026-11-04:* the maintainer made the key on their own
   computer, added the secret, and its public half is listed.
2. **Keyless short `LP-` codes pin with only 40 bits.** *Follow-up the same day:* new codes without a key are made in
   the LP2 form, which carries 80 bits (`servercode.encode`). Old short codes friends saved are still read, so retiring
   them breaks nothing; they get 80 bits once the host sends a new code.
3. **The meeting point on Lightsail.** Its TLS private key is inside the instance's start-up script. Rotate the
   certificate and move it to a file the start-up script does not carry, and check the instance's firewall. When the
   AWS connection was signed in again it reached a different account (one that holds only the CovenantWorks server).
   The meeting point's account needs to be connected for this.
4. **What the friends service can still see.**
   - The friend graph, message timing, and exact message lengths (messages are not padded).
   - On Windows, `catalog.json` (friend identity and pins) gets the folder's own permissions.
5. **Not pinned yet.**
   - `deploy/` images are not pinned by digest: Docker Hub refused with "too many requests".
   - Elevated netsh failures now report only an exit code.
