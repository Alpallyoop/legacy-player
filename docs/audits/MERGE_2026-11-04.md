# Joining `main` and `launcher-phases-1-4` (4 November 2026)

## Why a plain merge had too many conflicts

The two branches share no commit. `launcher-phases-1-4` started from "Backup of the working copy on S:" snapshots
(21 October onward), while `main` has its own history. The first backup's content matches `main` at v0.7.47
(`160f355`, 12 October), plus the work on the maintainer's computer that was prepared as 0.7.48 and never released.
Without a common commit, git compares every changed file from scratch, which is why the merge showed conflicts
everywhere.

## How it was joined

`main`'s seven commits after v0.7.47 were replayed one at a time onto `launcher-phases-1-4` (`git cherry-pick -x`, so
each commit names its original). Each conflict was decided on its own. Then a merge commit joined the two histories
without changing any file (`git merge -s ours --allow-unrelated-histories main`), so `main` can now fast-forward to
the result.

| `main` commit | What it brought | Decision |
|---|---|---|
| `45741d1` v0.7.49 | Home as the start page, Martin drawings, Dolphin-style controller mapping, TV pad fixes, release tag message | The mapping panel, its CSS, the help text and the Home default were taken. Hat-switch D-pads, which the branch's old wizard recorded, were added to the panel. The branch's Martin (one whole-body picture) and its single controller reader were kept, because the two sides had drawn Martin separately and the branch's reader is the newer one. The release workflow keeps the branch's injection-safe tag handling with `main`'s clearer error. |
| `7720287` docs | Version wording | The branch's docs were kept (they include the 1 November decisions). |
| `b738298` audit fixes | Bounded update download, no router redirects, signing only on `main` and tags | The branch already had stronger versions of the first two. The "only `main` and tags" signing rule was added to the workflow, and to the new update-signing step too. |
| `e5ea9b5` changelog | — | Empty after the above. |
| `d95d41d` mapping fixes | Named stick plots, box labels, unplugging a pad while mapping, a trusted hat axis | All taken. The branch's reader already trusts a hat axis only after seeing it at rest. It now also counts a hat diagonal as one move, as `main` decided. |
| `a718ae1` match key | The lobby never holds the match key (X25519 agreement) | Taken. It was also applied to the branch's Dolphin relay, which did not exist on `main`. |
| `2320c3c` uninstall | Never delete games or chosen save folders inside the data folder | Taken as it was. |
| `69b931a` v0.7.50 | Same-publisher check on update, restore on a failed swap | Taken, combined with the branch's re-check of the staged update. |

The version is **0.7.51**: `v0.7.50` is already a tag on `main` (its release was never published).

## Checked

The whole test suite under Python 3.13 with Playwright and Chromium. Three of `main`'s tests were adjusted to the
branch's controller reader:

- poll before reading;
- a held direction lets go below 0.3;
- the harness unplugs a pad by emptying its slot.

Two were adjusted to the agreed match key: an endpoint carries `pub`, never `psk`.

`tools/validate_repository.py`, `tools/check_links.py` and `tools/check_ui_syntax.js` are clean.
