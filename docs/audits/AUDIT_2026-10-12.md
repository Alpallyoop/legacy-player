# Re-audit of Legacy Player v0.7.46 (12 October 2026)

Scope: branch `launcher-phases-1-4` at `4ee3599`. Four reviews ran in parallel: friends and messages, TV mode,
consent, and general health. Each finding was checked against the code and by running the app (Playwright,
real `LauncherApp` instances and a real friends service subprocess), not taken from commit messages.
Not covered: real Windows hardware, real emulators, and the Constellation documents that `CLAUDE.md` lists
(the Constellation repository is not available to this audit).

Test suite: 806 tests, 3 skipped, 1 failure (`test_tv_mode.test_doctor_check_up_opens_in_tv_mode`, a brittle
test: it expects "still need" but the doctor correctly says "RetroArch is here but has no NES core yet" when
RetroArch is installed on the test machine).

## Summary

| Area | Verdict |
|---|---|
| Friends and messages | Built and working end to end, but two players on different networks usually can not reach each other's friends service. |
| TV mode | Real and mostly controller-driven, but many tasks hand off to desktop pages a controller can not use, and one bug can quit the app on a single press. |
| Consent | Partial. A privacy page and a record exist, but nothing checks the record before acting, about a dozen actions have no consent item, and several are on by default. |
| General | No critical defects. Some dead endpoints, stale docs and small UI issues. |

## 1. Friends and messages

Verified working through the real code paths: friend codes, request / accept / decline / withdraw, remove,
block / unblock, 1:1 messages, group chats, unread badge and in-app pop-ups, offline delivery (kept 7 days),
"now playing", invites into the Incoming tab, 500-character limit, rate limits, report to moderator, and the
moderation console (scrypt password + TOTP, CSRF, HttpOnly SameSite=Strict session). Messages are end-to-end
encrypted (X25519 + ChaCha20-Poly1305 + HKDF in `launcher/purecrypto.py` / `launcher/e2e.py`); a plaintext
canary never reached the service's storage. 78 friends tests pass.

Gaps:

1. **No reachable default service (blocker).** `friends_server` defaults to empty (`launcher/catalog.py:172`).
   Each player runs their own service on port 8791 or pastes a link. The link uses the public address, the
   router address if UPnP worked, or the LAN address (`launcher/app.py:1061`). The relay, lobby and server-code
   paths carry no friends traffic. Behind carrier-grade NAT or without UPnP, friends on different networks can
   not connect. This is the most likely reason friends looked "not implemented".
2. **Online status and notifications depend on the open window.** The heartbeat is sent only from page
   JavaScript (`index.html:3998`, `:4120`); the service marks you offline after 75 s. `launcher/tray.py` has no
   friends notifications.
3. **Invites need a secure (TLS) host server.** `_server_code_for_friends` returns "" otherwise
   (`app.py:978`), and Join then looks for the room on the wrong server.
4. Dead branches `friends_mod` `set_key` / `forget_key` (`app.py:1206-1210`).
5. No UI test drives two app instances against a live service.

## 2. TV mode

Working: enter with F11, Ctrl+Shift+T, the Games menu, the Guide button or Back+Start; start-in-TV-mode
(`start_page` default `"tv"`); home rows, game details, options, Start menu, room sheets, game picker, doctor
sheet, PC scan, add folder, an on-screen keyboard, and settings tiles, all by controller (D-pad, stick with
repeat, A/B/X/Y, bumpers, triggers).

Defects and gaps:

1. **Double press in dialogs (high).** The dialog controller loop returns before updating its previous-button
   state when no dialog is open (`index.html:4321`), so the A press that opens a dialog is read again inside
   it. "Quit Legacy Player" quits on one normal press with no confirmation; "More about this game" opens and
   closes at once.
2. **Controller dead ends.** These hand off to desktop pages with no controller support (focus stays on the
   page body): getting emulators, controllers, display, all settings, the doctor's office and every doctor
   fix, help, servers, privacy, saves, profile, storage, hidden games, and library sort/filter. Only Guide or
   Back+Start returns.
3. **Friends in TV mode are view-only.** Accepting or declining requests and reading or sending messages open
   the desktop Friends page (`index.html:4915-4922`).
4. **No server-code entry and no "start the match" in TV mode.** Join asks for a room code and then makes you
   pick the game by hand (`:5203`); the room sheet sends you to the desktop room page (`:5187`).
5. **Full screen** at startup works only through the Windows window placement (`launcher/winplace.py:331`);
   a gamepad press does not count as a user gesture for `requestFullscreen`.
6. `start_page="last"` never returns to TV mode (`catalog.py:104` has no `"tv"` choice).
7. **Console mode duplicates TV mode** with different button meanings (Y plays vs Y searches; LB/RB consoles
   vs rows). Both are in the Games menu and both are start-page choices.
8. Paging caps: 300 games per console row, 120 in the picker, 30 search results.

## 3. Consent

What exists: a privacy page with 8 items (`launcher/privacy.py`, `index.html:3790`), a turn-on dialog, a
per-item "privacy_ok" record, and a doctor "needs a look" flag. Downloads, installs, self-update, cover art,
game info, firewall rules, direct netplay, Dolphin NetPlay and problem reports are gated in Python and default
off.

Gaps:

1. **The record is never enforced.** No Python path checks it before acting; features run whenever their
   setting is on. The "informed" flag that counts as consent is sent by the page and can be claimed by any
   caller (`app.py:2429`). The record has no timestamp, policy version or history.
2. **Actions with no gate:** the router test (`app.py:4173`), router contact at startup to renew or close
   mappings (`:184`), the server name-tag claim, which sends `install_id` (`:2762`), putting an IPv6 or
   Tailscale address into the server code (`:4248`, `:4257`), Tailscale sign-in (dialog only), and the
   Start-menu shortcut.
3. **On by default without the player agreeing:** `server_auto_open` (UPnP for the server and the friends
   service), `auto_network_test` (pre-ticked on the welcome screen, which says every switch is off unless
   ticked; `index.html:1922`), `server_use_fallback`, `friends_share_room`, `dolphin_manage_pads` (writes into
   Dolphin's config).
4. **Shared with no switch of its own:** "now playing" goes to the friends service every 30 s; hole punching
   reveals your address during a match with only the general `allow_direct_connections` setting and no
   per-match confirm.
5. **Host address.** A server code is the host's IP, port and key, encoded (`launcher/servercode.py`). The
   app hides it on screen, but anyone with the code can decode it, and invites store it in plain text on the
   friends service (`server/social/__init__.py:502-507`). This conflicts with the requirement to keep the host
   address secret, with `privacy.py:50` ("never your address") and with PRIVACY.md.
6. **PRIVACY.md does not match the code:** it says the router opens only after a Windows prompt (UPnP has
   none) and that no identifiers are sent (`install_id` is).
7. No test checks that an action is refused when its consent is missing.

## 4. General health

All 124 UI calls have a backend handler, all 20 pages render with no console or page errors, and no security
defect was found in the local web server. Medium and low items:

- Endpoints never called by the UI: `api_find_games`, `api_private_link`, `api_monitors`,
  `api_network_check`; `api_dolphin_pads` and `api_engines_scan` are only used by tests.
- `docs/WBS.md`, `docs/REQUIREMENTS_TRACEABILITY.md` and `docs/PROJECT_SPEC.md` track only the research
  track; the shipped launcher has no work packages or requirement rows. `docs/ROADMAP.md` says v0.7.6.
  `docs/LIBRARY_AND_LAUNCHER_v1.md` has old paths and page names.
- **Governance conflict to raise, not fix silently:** Proposal 0002 (the launcher) is still "Proposed (not
  approved)" while the launcher ships. `docs/canonical/` has only `ECOSYSTEM_INTEGRATION.md`.
- `rescan` docstring misplaced and `_forget_emulators()` runs outside the scan lock (`app.py:245`).
- `server_control` captures process-wide stdout/stderr from other threads (`app.py:4029`).
- Storage says "across 1 games"; the doctor counts PC as a console ("0 of 19"); the contrast tool prints on
  every run; `"notices"` listed twice in `UNLOCKED`.

## Suggested order of work

1. Fix the TV dialog double press, and the brittle test.
2. Consent: a central check in Python enforced before every outbound or system-changing action, the missing
   items, defaults off until agreed, a timestamped and versioned record with revoke-and-undo, a complete
   first-run screen, and tests that each action is refused without consent. Bring PRIVACY.md in line.
3. Reachability: one rendezvous that carries both friends traffic and an opaque server code (a token, not an
   address), so friends work across networks and the host address stays private. This needs a decision on
   where it runs, because Legacy Player is local-first.
4. TV mode: controller versions of getting emulators, friend requests and messages, server-code entry and the
   room lobby; a controller focus mode for desktop pages; merge Console mode into TV mode.
5. Background heartbeat and tray notifications for friends.
6. Docs and the small items in section 4.

## Status after 0.7.47

Everything in the suggested order of work was done in 0.7.47 (see `CHANGELOG.md`). A verification pass over the
merged result then found and fixed: the TV Friends hub waiting forever without the friends permission or a friend
code, declined permissions being listed for review again, a cleared friends link hiding game-server friends, the TV
permission sheet showing empty fields, stale copy, dead UI functions, the Start menu shortcut surviving the in-app
uninstall, and settings saves racing background check-ins. Test suite: 894 tests, 3 skipped, all passing.

Still open, by design or needing a decision:

- **The host's address is still inside a server code.** Invites now carry it sealed end to end and friends on the game
  server need no code at all, but anyone given a server code can decode the address from it. Hiding it completely
  needs a relay or rendezvous run somewhere other than the host's computer, which conflicts with local-first. The
  permission texts and PRIVACY.md say this plainly.
- **Full screen at start on Windows** still relies on the window placement code, not the browser's full-screen flag
  (not testable here without a real Windows desktop).
- **Proposal 0002 approval and the missing canonical documents** are raised in
  `docs/proposals/2026-10-12-launcher-approval-and-canonical-docs.md` for the owner to decide.
- Not yet verified on real hardware: the tray notifications, the controller sheets with a physical pad, and friends
  between two real networks.
